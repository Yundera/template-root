# ensure-support-key.sh installs the ONLY lifetime credential on this host —
# admin's authorized_keys is never seeded from root's bootstrap key, so if this
# fails the orchestrator has no way back in after handover. It therefore runs as
# early as its dependencies allow: it needs the `admin` user (above), OPERATOR_API
# from the orchestrator-staged .pcs.env, and network. The support-key fetch is
# unauthenticated, so it needs neither docker, nor ensure-env-vars-valid.sh, nor
# ensure-yundera-user-data.sh's USER_JWT. Running it here (rather than ~15 scripts
# later, after the docker install) means the credential exists within seconds, and
# provisioning fails fast when the control plane is unreachable.
ensure-support-key.sh

# Backup (BACKUP-STORAGE-PLAN.md §6). Both MUST stay after
# ensure-yundera-user-data.sh, which supplies and rotates the USER_JWT the
# credentials call needs, and BEFORE ensure-mesh-installed.sh, whose stack-up is
# Maison's first boot: a freshly provisioned box then finds a connected
# repository (/DATA/AppData/kopia/engine) instead of coming up "not configured"
# and waiting a day. They need Docker and nothing of the mesh template.
#
# ensure-backup-credentials.sh MUST run before ensure-backup-config.sh: it writes
# the BACKUP_* values the second one renders. It does NOT call the API every night —
# every call mints a key and revokes the previous one, so it only calls when the
# credential is absent, near expiry, or was refused by the storage.
ensure-backup-credentials.sh
ensure-backup-config.sh
# The provider's IPv6 interface, so the mesh template's own ensure-public-ip.sh
# (PUBLIC_IP_MODE=interface) finds the address on its first run below.
ensure-ipv6-interface.sh
# THE STOCK MESH TEMPLATE (doc/mesh-stock-switch.md). The mesh, auth, maison and
# terminal stacks are Yundera/mesh-router-template-root's, unmodified, in
# /DATA/AppData/mesh — with their own self-check, cron (03:30), lock, log and
# update channel. This step installs it once through its install.sh (a fresh VM,
# an adoption, an identity change) and otherwise only writes the keys this
# template owns into its .env, running the mesh self-check when one changed.
# A failed install fails the self-check, and so a PCS create.
#
# BEFORE ensure-env-vars-valid.sh, which reads the keys the mesh template owns
# (public IP, default app, owner name) back into the unified .env; and before
# every gate below, since they all register with its auth-registrar. Its own
# inputs come straight from .pcs.env / .pcs.secret.env / .ynd.user.env, which
# ensure-yundera-user-data.sh above has filled.
ensure-mesh-installed.sh
ensure-env-vars-valid.sh
# The "Yundera Login" Dex connector: a drop-in in the mesh template's
# /DATA/AppData/auth/dex/connectors.d/. Runs the mesh ensure-dex.sh itself
# whenever the drop-in changes.
ensure-yundera-login.sh
# ensure-admin-gate-secret.sh MUST run before ensure-user-compose-stack-up.sh: it
# mints ADMIN_ASSERTION_SECRET into .pcs.secret.env / .env, which the admin gate
# and the admin app both interpolate. Without it the dashboard authenticates
# nobody (it fails closed). Enforced by order alone — self-check.sh re-runs this
# whole list when a sync changes it, so a newly-delivered script lands in its
# configured position rather than at the end.
ensure-admin-gate-secret.sh
ensure-user-compose-pulled.sh
ensure-user-compose-stack-up.sh

# The kopia stack — the resident backup engine Maison execs into
# (BACKUP_ENGINE_CONTAINER=kopia-engine in the mesh .env), plus kopia's own web UI
# behind an AppShield gate, which joins `pcs` and registers with the mesh
# template's auth-registrar. MUST stay after ensure-backup-config.sh: it reads the
# engine's hostname out of the repository.config that script writes, and a box
# that ran this first would bake in the synthetic fallback hostname instead.
# Nothing depends on it succeeding — Maison falls back to a one-shot engine
# container per command when the stack is absent or down.
ensure-kopia-stack.sh

# Maison's onboarding gate: writes or removes /DATA/AppData/maison/onboarding.json

ensure-maison-onboarding.sh
