# ensure-support-key.sh installs the ONLY lifetime credential on this host —
# admin's authorized_keys is never seeded from root's bootstrap key, so if this
# fails the orchestrator has no way back in after handover. It therefore runs as
# early as its dependencies allow: it needs the `admin` user (above), OPERATOR_API
# from the orchestrator-staged .pcs.env, and network. The support-key fetch is
# unauthenticated, so it needs neither docker, nor ensure-env-vars-valid.sh, nor
# ensure-yundera-user-data.sh's USER_JWT. Running it here (rather than ~15 scripts
# later, after the docker install) means the credential exists within seconds, and
# provisioning fails fast when the control plane is unreachable.
ensure-support-key.sh

# RENDER EVERYTHING, *THEN* BRING THE STACK UP. The auth block below all mints
# secrets and renders config files that services read at startup, and it must
# stay ahead of ensure-admin-gate-secret.sh — because that script does not just
# mint a secret, it calls ensure-user-compose-stack-up.sh itself to propagate it.
# On a cold provision that is the FIRST `docker compose up` on the box.
#
# It used to sit above this block, which meant the first up started Dex against a
# /DATA/AppData/yundera/dex/config.yaml that ensure-dex.sh had not written yet.
# `dex serve` on a missing config exits immediately, so Dex crash-looped under
# restart:unless-stopped for the ~2m45s until ensure-dex.sh ran — and on
# 2026-08-27 that loop lost Dex's then-pinned gRPC address to auth-registrar and
# wedged the whole provision. The address is gone (see docker-compose.yml), so
# the loop can no longer wedge anything, but a service that crash-loops on every
# cold provision is a standing liability. Keep this order.
#
# ensure-authelia.sh MUST run before ensure-dex.sh: it mints AUTHELIA_DEX_SECRET
# into .pcs.secret.env / .env, which ensure-dex.sh interpolates into the Dex
# "Local Account" connector's clientSecret.
ensure-authelia.sh
# ensure-yundera-login.sh writes dex/connectors.d/yundera.yaml, which
# ensure-dex.sh concatenates into the rendered config — so it belongs before it.
# Not a hard dependency: it re-runs ensure-dex.sh itself whenever the drop-in
# actually changed, which is also what covers the first cycle after this line is
# introduced (newly-added scripts run last in that one cycle).
ensure-yundera-login.sh
# ensure-dex-session-key.sh MUST run before ensure-dex.sh: it mints
# DEX_SESSION_KEY into .pcs.secret.env / .env, which ensure-dex.sh interpolates
# into `sessions.cookieEncryptionKey`. Unset renders an empty key, which Dex
# accepts (cookies simply go unencrypted), so this is an ordering requirement
# rather than a hard dependency.
ensure-dex-session-key.sh
# Cold-boot safe: ensure-dex.sh's trailing `docker restart dex` is guarded on the
# container existing, so running it before the stack has ever come up is a no-op.
ensure-dex.sh
# ensure-admin-gate-secret.sh MUST run before ensure-user-compose-stack-up.sh: it
# mints ADMIN_ASSERTION_SECRET into .pcs.secret.env / .env, which the admin gate
# and the admin app both interpolate. Without it the dashboard authenticates
# nobody (it fails closed).
ensure-admin-gate-secret.sh
ensure-user-compose-pulled.sh
ensure-user-compose-stack-up.sh

# Backup (BACKUP-STORAGE-PLAN.md §6). Both MUST stay after
# ensure-yundera-user-data.sh, which supplies and rotates the USER_JWT the
# credentials call needs, and before ensure-maison-stack.sh, so a freshly
# provisioned box finds a connected repository on Maison's first boot rather than
# coming up "not configured" and waiting a day.
#
# ensure-backup-credentials.sh MUST run before ensure-backup-config.sh: it writes
# the BACKUP_* values the second one renders. It does NOT call the API every night —
# every call mints a key and revokes the previous one, so it only calls when the
# credential is absent, near expiry, or was refused by the storage.
ensure-backup-credentials.sh
ensure-backup-config.sh

ensure-maison-stack.sh

ensure-maison-app-mirror.sh

ensure-maison-yundera-mirror.sh
